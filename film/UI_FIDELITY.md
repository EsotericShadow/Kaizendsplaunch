# UI fidelity: the Choroboros plate

The owner's note: "the built user interfaces are a little different than the actual user interface
in the app, so you should tighten that up". This file records what the film's plate
(`film/lib/plate.js`, `film/lib/topbar.js`) was checked against, what was changed, what still
differs and by how much, and how to repeat the checks. The film is now portrait and shows the plate
larger and in close-ups (knob macros up to about 2x), so crispness at scale is part of fidelity.

## Ground truth, in priority order

1. A real 1.0.5 screenshot from the owner. None exists yet: the branch has no new image files
   (checked with `git fetch` on 2026-09-29; the only images are the owner's art drop in
   `Choroboros/assets/`).
2. The editor source of the release candidate (2026-09-22). No newer head exists upstream. All
   geometry, drawing order, fonts, colours and animation values below come from it. The plate was
   measured against renders of that editor, built from the release candidate source in its release
   configuration (no developer tools, no developer licence keys, no local unlock) by a small harness
   kept outside this repo, painted with JUCE's own snapshot call at 2.19435x (1400 px wide, the
   plate's scale 1) and with every component's bounds dumped next to each render. As for a new,
   unregistered user, that editor shows only the free engines, so the renders cover Green and
   Purple, HQ off and on, at the treatment's settings and at the knob minimum, middle and maximum
   (7 states).
3. The owner's art in `Choroboros/` (switch panels, knob sheets, switch sheets, thumbs, fonts).
   The switch panels (`assets/switch-panels/<engine>-on.png`) are body-only renders of all five
   engines from an older layout (see "Blue, Red, Black and the white Create canvas").
4. Older captures (the site's `engines/` images, the earlier Pillow rebuild). They show an older
   header (bug, info, search and key buttons, a CREATE button, "1.0 HZ" readouts in
   Technology.ttf), so they are not used any more.

Per element (sub-pixel registration of each detail box, all 7 states, plate px at scale 1; 1
editor px = 2.19 plate px): every top-bar element (drawer, flask well, minus, plus, preset and
engine combos with their text and chevrons, wordmark, TRIM, meter) sits within 0.07 px; knobs within
0.41 px, the mix knob 0.10, the HQ lever 0.15, the COLOR thumb 0.13 (at 0, 50 and 100 %), the
resize grip 0.24, and the rate, offset, width and color readouts within 0.09 px. Three text runs sit
exactly one or two device pixels off, the same in every state (see "Open").

## What the plate now does, and why

### Window and scale

- The editor is 638 x 386 px at 1x: a 56 px top bar over a 638 x 330 body, laid out at a UI scale
  of 638 / 700 from the 700 x 363 design space. The plate uses one factor, K = 1400 / 638, for x
  and y (it used to scale the body's y by 725 / 330, which is 0.1 % taller than the editor). Window
  1400 x 847.02, body 1400 x 724.14, top bar 122.88 plate px.
- The body bitmap is the 1400 x 725 backpanel the product ships and draws. The editor stretches it
  into the 638 x 330 body, and so does the plate.
- Geometry (knobs, value boxes, COLOR slider, mix, HQ lever) is generated by
  `film/tools/rc_layout.py`, a port of the editor's layout code fed with the factory layout
  defaults it loads (not the `defaults_factory_mac.json` copy in the assets folder, which the
  editor never reads). `rc_layout.py --check` compares every rectangle with the component dumps of
  the real editor: 0 mismatches on all 7 states.
- Integer rounding follows JUCE: `roundToInt` rounds halves to even (216.5 -> 216), and
  `Rectangle<float>::toNearestInt` rounds x, y, w and h separately (`topbar.js` exports both).

### Top bar

Faithful to the release build's procedural header, at its default state (no hover, press, popup or
open drawer, since the film never shows a cursor). From left: the collapsed drawer with the pinned
Create well (flask icon) and its chevron; delete (-, disabled) and save (+); the Preset combo; the
KAIZEN DSP wordmark (the product's own white wordmark bitmap at 0.96); the engine selector; TRIM
with the 24-segment output meter at silence and "0.00 dB". There is no developer panel, feedback,
beta or version button: the release header has none. Fonts are the product's own IBM Plex Sans
Condensed SemiBold; icons are the product's SVGs, fitted the way JUCE fits a drawable.

Fixed in this pass: the "Preset" placeholder (and a Create draft's name in the engine selector) is
drawn from the combo's left edge, not the label's, so it moved 8 editor px left (it was 17.7 plate
px off); the chevron boxes now round half to even (they were 2 px off); and the drawer's chevron
fits its icon the way the editor does (it was 1.8 px off).

In trial mode the release header hides the wordmark and shows a "Trial: Nd" badge instead. The film
shows the free/licensed header, which is also what every free user sees.

### Value readouts

- Font: the layout's "technology" font id maps to JetBrains Mono SemiBold (the editor never loads
  `Technology.ttf`). The plate loads the npm `@fontsource/jetbrains-mono` 600 face (OFL). It is
  version 2.211 against the editor's 2.305: same metrics (600 advance, 1020 / -300), same shapes at
  readout sizes (outlines differ by a few redundant points). The owner's `Choroboros/assets/fonts/`
  has only ExtraBold, ThinItalic and NL weights, so it cannot supply SemiBold.
- Size: 13.67 editor px for the four main readouts and COLOR (15 design px x 638 / 700), 10.5 for
  Mix (the minimum). Colour: each engine's accent (Green #9dbd78, Blue #7fb8ff, Red #ff8d8b,
  Purple #b88dd8, Black #d4d4d4); the white Create draft uses #303030.
- Every character is drawn centred in its own slot (digits share one slot width); the run is
  centred in the box inset by 1 px. Per glyph: eight glow copies (alpha 0.40 x 0.14, spread 3.5 px
  for the main readouts), squashed top and bottom reflections with four blur copies each, then the
  glyph. Each engine's per-field offsets come from the layout defaults.
- A digit that changes flips over 60 ms: travel 0.25 px, fade, squash to 80 %, shear 0.30, clipped
  to its slot.

### Knobs, mix and HQ lever

- Main knobs: one sheet per control and HQ state (`<engine>_<n>_off.png`, `_on.png`), 10 x 10
  frames of 300 px (12 px border, 312 px step), read forward. The knob position p (0..1, linear in
  the parameter's raw value) maps to the angle 14 + 332 p degrees and to the NEAREST of the 100
  frames: frame = round((14 + 332 p) / 360 x 99). The factory layout asks for 156 frames, which the
  editor clamps to the 100 the sheet has.
- Factory mix knob: 13 x 12 frames of 512 px (64 px border, 576 px step), read in reverse:
  frame = round(155 - (14 + 332 p) / 360 x 155). The white Create mix sheet (1632 px) is 10 x 10
  frames of 150 px read FORWARD (the plate used to read it in reverse).
- While the HQ lever moves, the editor blends the off and on frames pixel by pixel,
  (1 - t) off + t on in premultiplied colour. The plate now does exactly that: both stacks in an
  isolated group, the on stack added with `plus-lighter` at t and the off stack at 1 - t (it used to
  lay the on frames over the off frames and fade the off frames out over the last fifth).
- HQ lever: each engine's own 18-frame sheet (5 columns, 512 px; frame 0 up = HQ on, frame 17 down =
  off), the white Create draft the shared `switch_a` sheet. Between two frames the editor blends
  (1 - a) base + a next; the plate now does the same (it used to lay the next frame over a fully
  opaque base). The owner's on/off "v2" switch sheets differ slightly (mean error about 3) from the
  per-engine sheets the product ships; the plate uses the shipped ones.

### The lit plate

The HQ "light on" plate is drawn by an overlay that caches the lit bitmap at its own size, 638 x 330
logical px, and draws that cache 1:1. On any screen above 1x (every Retina Mac) the lit plate is
therefore magnified from 638 px and visibly softer than the unlit plate. The plate now does the
same by default (`litPlate: "editor"`, the lit bitmap prepared at 638 x 330). This one change took
the HQ-on error from 2.31 to 1.62 (Green) and from 4.26 to 2.31 (Purple). `litPlate: "full"` shows
the sharp 1400 px lit bitmap instead. The lit plate's opacity follows the lever: 1 - frame / 17.

### COLOR slider thumb

JUCE indents a horizontal slider by min(12, h / 2) at each end. The editor draws the thumb at the
full slider height with the image's 1:2 aspect (at most 20 % of the width), travelling between
11.5 % insets, and hands its float rectangle to the int overload of `Graphics::drawImage`, so x, y,
w and h are truncated to whole editor px. The plate now truncates the same way; the thumb at 0 %
had been 1.1 plate px right of the real one. The white Create draft shows the default (green)
thumb, as the editor does.

### Labels drawn in code

The RATE, DEPTH, OFFSET, WIDTH, HQ, COLOR and MIX names are printed in the backpanel art; the
editor's own name labels are hidden on factory panels (the component dump shows only the six value
labels visible). Drawn in code are the six readouts, the top bar and the resize grip (JUCE's corner
component plus three grip strokes, #d7d2c6 at 0.34, 0.75 px).

## Close-ups

`plate.focus({ on, zoom, at })` puts a control ("rate", "mix", "hq", "color", or a readout such as
"depthValue") or a body point at a screen point and scale. Everything stays a DOM layer under one
CSS transform, so every bitmap is resampled once, from its source pixels to the screen, and text
and the top bar stay vector.

- Backpanel: above scale 1 the plate switches to a prepared 2800 x 1450 plate
  (`film/tools/prep_gui.py`, `/data/gui/plates2x`) for Green, Blue, Red and Purple. The product's
  own 2800 px art is not exactly the shipped 1400 px bitmap at 2x: Green is offset by about 2.7 px
  and scaled 0.4 %, Red by about 9 px and 1.3 %, and every lit plate has a different lamp glow. So
  each 2x plate is the shipped bitmap upsampled plus only the fine detail of the 2800 px art,
  registered to it (fitted scale and offset, residual under 0.2 px). Reduced to 1400 px it equals
  the shipped bitmap (mean error 0.37-1.0), so the switch at scale 1 is invisible. The lit 2x plate
  is sharper than the editor's 638 px lit cache, so it fades in between scale 1.0 and 1.25. Black
  has no higher-resolution source (its extra plate is a 1024 px legacy copy), and neither does the
  white Create canvas: those magnify the shipped 1400 px bitmap.
- Knobs: 300 px source frames for a 278.7 px knob at scale 1, so a 2x close-up magnifies them
  1.86x. That is the product's highest-resolution knob art. The owner's 512 px, 156-frame knob
  sheets are a different, older render (another snake ring, dial and perspective), so they cannot
  stand in for it.
- Mix knob: 512 px frames for a 116 px knob, native to about 4x. HQ lever: 512 px frames for a
  252 px cell, native to about 2x. Readouts and top bar: vector at any scale.
- Pass `hiRes: true` to a plate built small that `focus()` pushes in later. The 2x plates are
  decoded before frame 0 like every image, at about 32 MB per plate, so they load only when asked
  for or when the plate is built above scale 1.

## Blue, Red, Black and the white Create canvas

The release editor shows paid engines and Create only to licensed or trial users, so no editor
render of them was made. What was checked:

- Geometry comes from the same layout code and defaults, per engine (Blue's 112 px knobs, Red's
  115 px knobs and its own HQ lever offset, Black's layout). The port reproduces the real editor's
  rectangles exactly on Green and Purple.
- Art identity was checked against the owner's switch panels for all five engines (side by side,
  50 % blend and difference images, registered on the backpanel texture): same backpanels, knob
  art, thumbs and levers. Those panels are an older layout, stretched to 2:1 and with smaller,
  differently placed knobs (7-42 plate px away; the HQ lever agrees within about 1 px), so they are
  not a geometry reference.
- The white Create canvas is the clean white draft ("New Engine"): white main and mix sheets, the
  shared lever sheet, the default green COLOR thumb and readouts in #303030 (the plate used to
  hide the thumb and readouts). It is drawn on the Green factory geometry. Its printed windows,
  recesses and labels line up with the plate's readouts, knobs and slider (side by side and blend
  against the bare white backpanel).

## Open

- "0.00 dB" in the top bar sits 0.9 editor px (2 plate px at scale 1) higher than in the real
  editor, the same in every state. Its box, font and size match the paint code, and the combo text,
  laid out the same way, matches within 0.02 px. The cause was not found.
- The Depth and Mix readouts sit 1 plate px higher than the real ones in every state, while Rate,
  Offset, Width and Color match. This is rasteriser rounding at the reference scale: JUCE's
  software renderer rounds glyph baselines to whole device pixels, and Blink rounds font ascent and
  descent to whole pixels. The error is at most one device pixel at any scale.
- The HQ-on knobs keep a slightly higher error (2.5-5 against 1.6-2.5 for HQ off) from resampling
  the lit knob art. Frames and positions match.
- Blue, Red and Black geometry, and the white canvas on the Green geometry, are not verified
  against a render of the real editor. A 1.0.5 screenshot of any of them (or a licensed render)
  would settle it.
- Hover, press, popup, open-drawer and trial-badge states of the top bar are not modelled.
- `film/tools/verify_plate.py` and `film/gallery/verify.html` measure against the old captures
  (lowest priority). They predate the top bar and are superseded by the tools below.

## Repeating the checks

```sh
film/film.sh stills fidelity-now $(python3 -c "print(','.join(str(i+0.5) for i in range(17)))") film/gallery/fidelity.html
python3 film/tools/fidelity_compare.py /home/user/build/film/stills/fidelity-now <editor renders> /home/user/build/film/stills/fidelity now
python3 film/tools/fidelity_offsets.py <editor render.png> <matching still.png>
python3 film/tools/fidelity_panels.py /home/user/build/film/stills/fidelity-now /home/user/build/film/stills/fidelity now
python3 film/tools/rc_layout.py --check <editor component dumps>
film/film.sh check 1.5,9.5,13.5,15.5 film/gallery/fidelity.html
```

`film/gallery/fidelity.html` shows one plate per second: the 7 reference states, then the
switch-panel pose for Green, Blue, Red, Purple, Black and the white canvas, then four close-ups
(Green Rate knob at 2x with HQ off, Green Mix at 2x lit, the Purple Depth readout at 3x lit, the
Green HQ lever at 2x lit). The editor renders, their component dumps and every comparison image
live under `/home/user/build/film/` (`ui-snap/out`, `stills/fidelity/`), never in this repo.
